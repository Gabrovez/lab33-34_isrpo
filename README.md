## Описание проекта

Это ASP.NET Core Web API приложение «Заметки» — полноценный CRUD-сервис с поддержкой категорий, фильтрации, пагинации, валидации и единого формата ответов.  

Приложение реализует связь «один ко многим»: одна категория может содержать много заметок. Все операции защищены от некорректных данных, а архитектура построена на паттерне Repository для чистого разделения логики.

Идеально подходит для обучения или как бэкенд для фронтенда (React/Vue/Angular) — все ответы предсказуемы, ошибки понятны, документация через Swagger.

## Паттерн Repository: зачем он нужен?

Паттерн **Repository** — это прослойка между контроллерами и базой данных. Он изолирует логику доступа к данным, делая код чище, тестируемее и масштабируемее.

### Без Repository:
```
Контроллер → напрямую работает с DbContext → База данных
```
→ Логика запросов размазана по контроллерам  
→ Трудно тестировать без реальной БД  
→ При смене БД нужно менять всё

### С Repository:
```
Контроллер → Repository → DbContext → База данных
```
✅ Все запросы к БД в одном месте  
✅ Можно подменить репозиторий на мок при тестировании  
✅ При смене БД меняем только реализацию репозитория  
✅ Контроллер не знает про EF Core — только про интерфейс


## Главные выводы

1. **Repository — не лишняя абстракция**, а способ держать код управляемым при росте проекта.
2. **Data Annotations** решают двойную задачу: валидируют входные данные и задают ограничения в БД.
3. **Единый формат ответа (`ApiResponse`)** упрощает жизнь фронтенду — он всегда знает, что ждать от сервера.
4. **`DeleteBehavior.Restrict`** защищает данные от случайного каскадного удаления.
5. **`Include()` + проекция в DTO через `Select()`** — правильный способ получить связанные данные без N+1 проблемы.
